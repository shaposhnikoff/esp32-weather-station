# Сборка и прошивка погодной станции

Инструкция для подключённой платы ESP32-S3: **16 MB Flash, 8 MB PSRAM,
экран 1024 × 600**, профиль `waveshare-lcd5b`. Профиль `waveshare-lcd5`
предназначен для другого экрана, 800 × 480.

Если на плате последней записана погодная станция с этой разметкой,
для обычного обновления используй раздел **«Обновить только приложение»**.
Если после неё загружали другой проект, сначала восстанови весь комплект
погодной станции и заново загрузи конфигурацию. Другой проект может заменить
таблицу разделов или перезаписать область прежних настроек.

## Подготовить Mac

Нужны Command Line Tools для Xcode, UV, PlatformIO и SDL2.
В этом проекте CMake и Ninja запускаются через UV в закреплённых версиях;
отдельно устанавливать их не нужно.

```sh
xcode-select -p
brew install uv sdl2
```

Если PlatformIO ещё не установлен:

```sh
uv tool install --python 3.12 platformio
```

Дальнейшие команды выполняй из корня проекта, в одном терминале:

```sh
git clone git@github.com:shaposhnikoff/esp32-weather-station.git
cd esp32-weather-station
export PLATFORMIO_CORE_DIR="$HOME/.platformio"
export PATH="$PLATFORMIO_CORE_DIR/penv/bin:$PATH"

PORT=/dev/cu.usbmodem21211201
BUILD=.pio/build/waveshare-lcd5b
PYTHON="$PLATFORMIO_CORE_DIR/penv/bin/python"
ESPTOOL="$PLATFORMIO_CORE_DIR/packages/tool-esptoolpy/esptool.py"
```

Эти пути соответствуют проверенной установке на текущем Mac. При другой
установке выполни `pio system info`: `PYTHON` должен указывать на показанный
`Python Executable`, а `ESPTOOL` — на `packages/tool-esptoolpy/esptool.py`
в показанном `PlatformIO Core Directory`. Помощник `provision-config.sh`
рассчитан на установку Python в `$PLATFORMIO_CORE_DIR/penv/bin/python`,
как на этом Mac; для другой установки используй ручную запись готового образа.

`PORT` — обнаруженный порт этой платы. После переподключения он может измениться:

```sh
pio device list
```

Используй USB-кабель с передачей данных. Перед записью закрой serial monitor
и другие программы, которые держат этот порт.

## Собрать и проверить

```sh
make firmware
make desktop
uv tool run --python 3.12 --from cmake==3.30.5 \
  --with ninja==1.11.1.3 ctest --test-dir build-desktop --output-on-failure
```

`make firmware` собирает `waveshare-lcd5b` последовательно, с `-j 1`.
В этой среде параллельная сборка ранее приводила к ошибке импорта SCons.
Первый запуск скачивает SDK и библиотеки.

Готовые файлы:

| Файл | Назначение | Адрес |
| --- | --- | --- |
| `.pio/build/waveshare-lcd5b/bootloader.bin` | Загрузчик | `0x0` |
| `.pio/build/waveshare-lcd5b/partitions.bin` | Таблица разделов | `0x8000` |
| `.pio/build/waveshare-lcd5b/firmware.bin` | Приложение | `0x10000` |

Приложению выделено 6 MiB. Все три файла для первоначальной записи должны
происходить из одной сборки.

## Первая запись или восстановление загрузчика

Эта команда заменяет загрузчик, таблицу разделов и приложение. Для обычного
обновления уже работающей станции она не нужна.

```sh
"$PYTHON" "$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 460800 \
  write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB \
  0x0 "$BUILD/bootloader.bin" \
  0x8000 "$BUILD/partitions.bin" \
  0x10000 "$BUILD/firmware.bin"
```

**Заголовок загрузчика должен быть DIO.** Принудительная запись с
`--flash_mode qio` уже вызывала на этой плате чёрный экран и циклические
ROM watchdog resets. После запуска загрузчик сам включает QIO;
`board_build.flash_mode = qio` в настройках сборки менять не нужно.
Ожидаемый режим записи также указан в сгенерированном
`.pio/build/waveshare-lcd5b/flasher_args.json`.

Без следующего шага новая плата покажет ошибку конфигурации. Это ожидаемо:
в прошивке нет встроенных реквизитов Wi-Fi.

## Подготовить внешний config.json

Все пользовательские настройки находятся в одном файле. При старте прошивка
полностью проверяет его, затем применяет настройки. Изменения вступают в силу
после перезагрузки; пересборка приложения не требуется.

Создай приватную копию шаблона вне проекта:

```sh
install -d -m 700 "$HOME/.local/share/weather-station/config"
CONFIG="$HOME/.local/share/weather-station/config/config.json"
if [ ! -e "$CONFIG" ]; then
  cp config.example.json "$CONFIG"
fi
chmod 600 "$CONFIG"
```

Существующий приватный файл эта команда сохраняет; редактируй его,
не заменяя шаблоном.

Открой этот файл текстовым редактором и заполни:

| Поле | Значение |
| --- | --- |
| `schema_version` | `1` |
| `mode` | `weather` для реальной погоды; `demo` или `diagnostics` для явных тестовых режимов |
| `wifi.ssid` | Имя сети Wi-Fi 2,4 GHz, до 32 байт |
| `wifi.password` | Пароль 8–63 байта, 64 шестнадцатеричных символа либо пустая строка для открытой сети |
| `wifi.ntp_server` | Имя сервера времени, например `pool.ntp.org` |
| `location.name` | Название на экране |
| `location.latitude`, `location.longitude` | Координаты в градусах |
| `location.timezone` | IANA timezone для погодного API, например `Europe/Kyiv` |
| `location.posix_timezone` | Соответствующие локальные правила времени, включая DST |
| `display.brightness` | Целое число `0`–`100`; `0` выключает подсветку, промежуточные значения дают программное затемнение |
| `display.large_text` | `true` или `false` |
| `weather.update_seconds` | Интервал обновления, `60`–`86400` секунд |
| `weather.request_timeout_ms` | Таймаут HTTPS, `1000`–`60000` миллисекунд |
| `weather.stale_after_seconds` | Порог устаревания, от интервала обновления до `604800` секунд |
| `weather.cache_write_seconds` | Минимальный интервал записи кеша, `60`–`86400` секунд |

Все поля обязательны. Неизвестные и повторяющиеся поля, неверные типы и файлы
больше 8192 байт отклоняются. Не добавляй комментарии в JSON.
Для Киева шаблон уже содержит согласованную пару:
`Europe/Kyiv` и `EET-2EEST,M3.5.0/3,M10.5.0/4`.
Поддерживаются POSIX timezone с буквенными сокращениями, числовыми смещениями
и двумя явными правилами `Mmonth.week.weekday` при наличии DST.

Проверка не печатает секретные значения:

```sh
./build-desktop/weather-config-check "$CONFIG"
```

## Загрузить настройки без пересборки

```sh
sh tools/provision-config.sh "$CONFIG" "$PORT"
```

Помощник проверяет JSON, при необходимости собирает закреплённую версию
нативного генератора LittleFS, создаёт временный приватный образ и записывает
только раздел конфигурации. По окончании плата перезагружается, временная
копия и образ удаляются. Исходный приватный файл остаётся на компьютере.
Для первого запуска помощника нужен доступ к GitHub.

Расположение данных:

| Раздел | Адрес | Размер | Использование |
| --- | --- | --- | --- |
| `config` | `0x610000` | 1 MiB | LittleFS, `/config/config.json`, только чтение в прошивке |
| `cache` | `0x710000` | 1 MiB | LittleFS, последний корректный прогноз |

При ручной подготовке образа используй блоки 4096 байт, размер 1048576 байт
и генератор с `LFS_NAME_MAX=63`. В образе должен быть файл `/config.json`.
Готовый приватный образ записывается так:

```sh
"$PYTHON" "$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 460800 \
  write_flash 0x610000 /private/path/config.bin
```

Не добавляй настоящий `config.json`, образы конфигурации и полные дампы Flash
в репозиторий или общий архив прошивки. Они могут содержать пароль.

## Обновить только приложение

После изменения кода, если на плате сохранилась совместимая разметка
погодной станции:

```sh
make firmware
"$PYTHON" "$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 460800 \
  write_flash 0x10000 "$BUILD/firmware.bin"
```

Эта запись сохраняет загрузчик, таблицу разделов, конфигурацию и кеш.
Она подходит, пока `partitions.csv` не менялся. Если изменена разметка,
сначала проверь новые адреса и содержимое затрагиваемых разделов, затем
выполни первоначальную запись и загрузку конфигурации.

Для отката приложения запиши ранее сохранённый рабочий `firmware.bin`
той же разметки по адресу `0x10000`.

## Проверить работу после записи

В выводе esptool должны быть `Hash of data verified` и успешное завершение.
Открой журнал и нажми RESET на плате:

```sh
pio device monitor --port "$PORT" --baud 115200
```

Выход из монитора — `Ctrl+C`. Признаки нормального запуска:

```text
mode:DIO
Found 8MB PSRAM device
Weather UI ready: ... panel=1024x600 mode=0
Wi-Fi connected; IP acquired
LIVE weather received: HTTP 200, temperature ... C, hours=120
```

Последние две строки подтверждают подключение и настоящий ответ Open-Meteo.
В режиме `weather` на экране не должно быть метки демо. Проверь название
места, дату обновления, прогноз и открытие карточек касанием.

Начальное подключение, синхронизация времени и HTTPS занимают время.
Для сети нужны доступ к серверу NTP и HTTPS API Open-Meteo. Проверка
TLS-сертификата включена. После ошибки сохраняется последний корректный
прогноз, повторные запросы выполняются с паузой; кнопка обновления не обходит
минимальный интервал 60 секунд.

Для проверки того же интерфейса на Mac:

```sh
./build-desktop/weather-preview --config "$CONFIG"
```

## Если запись или запуск не удались

- **Порт занят:** закрой serial monitor и другие программы с этим USB-портом.
- **Нет подключения esptool:** удерживай BOOT, нажми и отпусти RESET, отпусти
  BOOT и повтори запись. Если соединение нестабильно, используй `--baud 115200`.
- **Чёрный экран и ROM watchdog reset:** проверь профиль `waveshare-lcd5b`
  и восстанови загрузчик командой первоначальной записи с DIO.
- **Ошибка config.json:** исправь поле, указанное `weather-config-check`,
  и повторно загрузи весь файл помощником.
- **`partition "config" could not be found`:** отсутствует нужная запись
  в таблице разделов. Повторная загрузка JSON сама по себе её не создаст.
  Если перед этим прошивали другой проект, восстанови загрузчик, таблицу
  и приложение погодной станции из одного комплекта, затем загрузи JSON.
- **Нет Wi-Fi:** проверь имя сети, пароль и наличие сети 2,4 GHz в приватном
  файле, затем снова загрузи конфигурацию.
- **Wi-Fi подключён, но HTTPS не работает:** проверь доступ к NTP, DNS и
  Open-Meteo; сохрани журнал ошибки без реквизитов сети.

Полное стирание Flash для штатного обновления не требуется. Перед работой с
неизвестной разметкой можно сохранить полный приватный дамп:

```sh
umask 077
"$PYTHON" "$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 460800 \
  read_flash 0x0 0x1000000 "$HOME/weather-station-full-backup.bin"
```

Копия только первых 2 MiB содержит не весь Flash.
Для полного резервирования этой платы размер дампа должен быть **16 MiB**.
